Sibling packages — what we own

The pipeline orchestrates several sibling Python packages. Most are our own forks or clean-room re-implementations — installed editable in dev, baked into the shifter image for batch runs.

PackageOriginRoleStatus
SLAy Our fork (post-merge step) Template-similarity unit merging after kilosort. Fixes the "axon arbor split across N sibling clusters" problem. v1 stable
kssynth Our package, new Reconstructs a "synthesized" Kilosort folder layout from any per-unit template set. Lets recon-stage phases consume kssynth output as if it were KS native — decouples reconstruction from KS internals. v1 feature-complete · 58 tests
unitlink Our wrapper over UnitMatchPy Cross-session unit matching (same neuron, multiple DIVs). Two-halves UMPy backend; output is a per-(chip, well) match table. v1 feature-complete · 53 tests
radivojevic2023_recon_algo Clean-room re-impl of Radivojevic 2023 (eLife 86512) Alternative reconstruction algorithm. Three-stage: adaptive thresholding → skeletonization → multi-step tracking. Compared against axon_velocity_gtrs. Stage 1 done · 81 tests
axon_velocity Buccino 2022 (upstream) Current production reconstruction algorithm; consumed via axon_velocity_gtrs phase. PyPI pin. 3rd-party
UnitMatchPy Upstream Underlying cross-session matcher; unitlink wraps it. 3rd-party
bombcell Upstream (Julie Fabre lab) Per-unit quality metrics + good/mua/noise labels post-KS. Phase exists in the spikesort stage but is currently bypassed — recon-stage QC reads KS4-native labels from cluster_KSLabel.tsv directly. disabled

Integration shape

🔌 How they wire in
  • Each sibling is a separate git repo + pyproject.toml package.
  • Dev: pip install -e ../pkgs/<sibling> via tools/setup_env.sh --editable-siblings.
  • Container: pinned to commit at build time via Dockerfile ARGs; rebuilt + pushed to docker.io/adammwea/axon-recon:pipeline-v2 as deps change.
  • Phases call them via thin adapter functions in pipeline/stages/<stage>/phases/ — phase shape is the contract, library version can swap.
🧱 Why so many own-pkgs
  • SLAy: original was fragile on big wells; we own the merge logic now and fix bugs in-tree.
  • kssynth: needed to make reconstruction inputs independent of "must run KS first" — opens the door to synthetic templates, ablations, cross-algorithm comparisons.
  • unitlink: thin shim so cross-session matching speaks our data layout, not UMPy's expected one.
  • radivojevic: no public code release for the paper — clean-room was the only path.
