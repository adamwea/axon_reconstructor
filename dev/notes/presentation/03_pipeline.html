Pipeline architecture — 6 stages

Each stage is a directed graph of phases. Phases are independently re-runnable, checkpoint-marked (ok / error / stale / in_progress), and addressable from the CLI (axon-recon stages reconstruct.kssynth ...).

init
Resolve dataset + well + run scope. YAML config → runtime config tree.
▸
preprocess
Bandpass + common-reference. Metadata extraction (sample rate, electrode positions).
▸
spikesort
Kilosort 4 → SLAy template-similarity merge. Output: clean post-merge unit IDs. (Bombcell QC is currently bypassed — labels are KS4-native.)
▸
reconstruct
Spike-triggered averages → axon arbor (axon_velocity_gtrs; + Radivojevic in progress).
▸
analysis
Per-unit metrics → cross-session matching (unitmatch). Aggregation for dashboard.
▸
cleanup
Prune intermediate analyzers; status replay; archive.
🏗️ Engineering invariants
  • Restart semantics: three modes — no-flag (auto-restart from first broken phase), --force-restart (rmtree everything), --replot (re-run plot/report phases only).
  • Checkpoint markers: every phase writes summary.json with status before/after work. Stranded in_progress = crashed process → auto-restart catches it.
  • Process control: --targets / --limit-wells / --target-pairs CLI flags for surgical re-runs; --force-enable PHASE to override YAML-disabled phases for smokes.
  • Container parity: shifter image adammwea/axon-recon:pipeline-v2 built from pyproject.toml extras; sibling pkgs installed as editable in dev, baked-in in container.
📂 Data flow on disk
analyzed_data/<experiment>/<date>/<chip>/AxonTracking/
  <rec>/<well>/
    preprocess_outputs/        # filtered traces, metadata
    spikesort_outputs/
      sorter_output/           # kilosort 4 raw (KS4-native labels in cluster_KSLabel.tsv)
      sorter_output_snapshot/  # snapshot before SLAy mutates aux TSVs
      merge_SLAy/              # post-merge IDs + diagnostics
      analyzer_output/         # spike-interface analyzer (recording_info + sorting)
    recon_outputs/             # axon arbors per unit ← canonical reference
      reports/                 # chip layout, circle_recon_grid
      units/<unit_id>/         # circle_recon, template_circles
      context/                 # branch_propagations, velocities
    unitmatch/<chip>/<well>/   # cross-DIV matches (in progress)
Why this structure: phase-grain checkpointing means any failed step can be retried without re-running the expensive upstream (kilosort + spike-template extraction ≫ everything else). Restart correctness is what makes the pipeline tractable on 32-cohort overnight runs.
